# 005 — MovieNight: группы в боте (дублирование Mini App)

**Статус:** READY
**Модуль:** movienight (existing после 004)   **Бриф:** docs/product/movie-night.md (Этап 1, часть 2 из 2;
«Дополнения после проверки Этапа», п. 0)
**Зависит от:** 003 (`MapReply`, `EditAsync`, `IDeepLinks`), 004 (`IGroupService`, БД модуля, правила владельца).

## Исходное описание
Этап 1 (группы) + дополнение: «продублировать функции, которые появятся в Mini App, через inline команды в боте,
чтобы была возможность работать с ботом через контекстное меню в Telegram».

## Цель
Всё, что 004 даёт в Mini App для групп, доступно в личном чате с ботом: команды в меню «/» и inline-кнопки, ввод текста
по запросу бота. Бизнес-логика и права — только `IGroupService` из 004; бот — тонкий слой `Telegram/`.

## Сценарии
1. `/groups` → «Ваши группы:» с кнопкой на каждую группу и «Создать группу».
2. «Создать группу» → «Как назовём группу?» → пользователь пишет «Киноклуб» → карточка группы.
3. Карточка: участники по порядку с пометкой владельца, кнопки «Пригласить», «Выйти из группы», «К списку групп»,
   «Открыть приложение»; владельцу ещё «Переименовать», «Новая ссылка», «Участники» (исключение).
   Переходы между меню — редактированием того же сообщения.
4. «Пригласить» → отдельное сообщение с приглашением и ссылками — для пересылки.
5. Друг открывает `t.me/<bot>?start=movienight_join_<код>` → «Приглашение в группу …» → «Вступить».
6. Владелец: «Участники» → «Исключить Васю» → «Да, исключить».

## Критерии приёмки
Все сценарии вызывают `IGroupService` (004); в тестах — реальная БД модуля и захват `IMessageSender` (`SendAsync`/`EditAsync`).
Имена, порядок, правило получателей уведомлений — как в 004.

### Команды и создание
- **AC-1** Given модуль зарегистрирован When старт Host Then `SetMyCommands` содержит после платформенных
  `groups` — «мои группы», `newgroup` — «создать группу» (в этом порядке); `/help` — соответствующие строки.
- **AC-2** Given у пользователя группы A (2 участника, он владелец) и B (1) When `/groups` Then новое сообщение
  «Ваши группы:», inline-клавиатура: по строке на группу в порядке 004 AC-5 с текстом «{name} · {N}» (у групп, где он
  владелец, — «★ {name} · {N}») и callback `movienight:g:{id}`, последняя строка — «➕ Создать группу» (`movienight:new`).
  Given групп нет Then «У вас пока нет групп. Создайте группу и пригласите друзей.» и только «➕ Создать группу».
- **AC-3** Given `/newgroup   Киноклуб  ` Then группа «Киноклуб» создана, ответ — карточка (AC-6) новым сообщением.
  Given `/newgroup` без аргументов Then «Как назовём группу? Отправьте название одним сообщением (до 64 символов).»
  с кнопкой «Отмена» (`movienight:cancel`) и `ExpectReplyAsync(user, "movienight", "newname", null)`.
  Given аргумент невалиден по 004 AC-3 Then «Название должно быть от 1 до 64 символов, без переводов строк.», группа
  не создана, ожидание не ставится. Given лимит 004 AC-4 Then «Можно состоять не больше чем в 20 группах.»
- **AC-4** Given ожидание `newname` When текст «Киноклуб» Then группа создана, карточка новым сообщением.
  When текст невалиден Then «Название должно быть от 1 до 64 символов, без переводов строк. Попробуйте ещё раз.» и
  ожидание ставится снова. When лимит Then текст лимита, ожидание не ставится.
- **AC-5** When `movienight:new` Then новое сообщение-вопрос и ожидание — как AC-3 без аргументов.
  When `movienight:cancel` Then `CancelAsync(user)`, сообщение с кнопкой редактируется в «Хорошо, отменили.» без клавиатуры.

### Карточка и навигация
- **AC-6** When `movienight:g:{id}` от участника Then сообщение **редактируется** в карточку:
  ```
  Группа «{name}»
  Участники (по порядку вступления):
  1. Аня (вы) — владелец
  2. Петя
  ```
  Клавиатура не-владельца (по строкам): [«Пригласить» `invite:{id}`] [«Выйти из группы» `leave:{id}`]
  [«« К списку групп» `groups`] [«Открыть приложение» — `web_app` на `IDeepLinks.WebAppUrl`; строки нет при `null`].
  Владельцу после «Пригласить» добавляются строки: [«Переименовать» `rename:{id}`] [«Новая ссылка» `newlink:{id}`]
  [«Участники» `members:{id}`] — только если в группе больше одного участника для «Участники».
  (Здесь и далее callback data указана без префикса `movienight:`.)
- **AC-7** When `movienight:groups` Then сообщение редактируется в список (AC-2). Повторное нажатие без изменений —
  без ошибки (003 AC-11).
- **AC-8** Given `{id}` группы, где пользователь не участник/группы нет, или `{id}` не GUID When любой колбэк с `{id}`
  Then `AnswerAsync("Вы не состоите в этой группе", showAlert: true)` и сообщение редактируется в список (AC-2).
- **AC-9** Given не-владелец нажимает колбэк владельца (`rename`, `newlink`, `newlinkok`, `members`, `kick`, `kickok` —
  например, на старом сообщении, после смены владельца) Then `AnswerAsync("Это может сделать только владелец группы.",
  showAlert: true)`, сообщение редактируется в актуальную карточку; изменений нет. Ответ текстом `rename` от
  не-владельца → тот же текст новым сообщением.
- **AC-10** When `invite:{id}` Then **новое** сообщение: «Присоединяйся к группе «{name}» в Киновечере!\n
  Открыть приложение: {miniAppLink}\nЧерез бота: {botLink}»; `AnswerAsync()` без текста. Given ссылки `null`
  (`Bot:Username` не задан) Then `AnswerAsync("Ссылка-приглашение недоступна", showAlert: true)`, сообщение не шлётся.

### Действия владельца
- **AC-11** When `rename:{id}` (владелец) Then новое сообщение «Новое название для группы «{name}»? Отправьте одним
  сообщением (до 64 символов).» с «Отмена» и `ExpectReplyAsync(user, "movienight", "rename", "{id}")`.
  Ответ текстом → переименовано, новое сообщение — карточка; невалидный — как AC-4 (ожидание снова); пользователь
  больше не участник → «Вы не состоите в этой группе»; больше не владелец → AC-9.
- **AC-12** When `newlink:{id}` Then редактирование в «Старая ссылка перестанет работать. Создать новую?» с
  [«Да, новая ссылка» `newlinkok:{id}`] [«Отмена» `g:{id}`]. When `newlinkok:{id}` Then `RegenerateInviteAsync`,
  сообщение редактируется в карточку, `AnswerAsync("Создана новая ссылка")` и **новое** сообщение-приглашение
  (как AC-10) с новыми ссылками.
- **AC-13** When `members:{id}` Then редактирование в «Участники группы «{name}»:» + клавиатура: на каждого участника,
  кроме себя, строка «Исключить {displayName}» `kick:{id}:{joinSeq}`; последняя — «« К группе» `g:{id}`.
  When `kick:{id}:{joinSeq}` Then редактирование в «Исключить {displayName} из группы «{name}»?» с
  [«Да, исключить» `kickok:{id}:{joinSeq}`] [«Отмена» `members:{id}`]. When `kickok` Then `RemoveMemberAsync`,
  редактирование в список участников (AC-13 заново), `AnswerAsync("{displayName} исключён(а) из группы")`;
  уведомления — 004 AC-12. Given членство `{joinSeq}` уже не существует (участник вышел/переподключился) Then
  `AnswerAsync("Этот участник уже не в группе", showAlert: true)` и актуальный список участников.
  `joinSeq` — `MemberInfo.JoinSeq` (004), а не `userId`: так callback data укладывается в 64 байта.

### Выход
- **AC-14** When `leave:{id}` Then редактирование в «Выйти из группы «{name}»?» (владелец при других участниках:
  «Выйти из группы «{name}»? Владельцем станет {displayName следующего}.») с [«Да, выйти» `leaveok:{id}`]
  [«Отмена» `g:{id}`]. When `leaveok` Then `LeaveAsync`, редактирование в «Вы вышли из группы «{name}».» + кнопка
  «« К списку групп». Уведомления и передача владения — 004 AC-18, AC-19.

### Вступление через бота
- **AC-15** Given `/start movienight_join_AB12cd34EF` (код действует, пользователь не участник) Then
  «Приглашение в группу «{name}»\nУчастники: {имена через запятую}» с [«Вступить» `join:AB12cd34EF`]
  [«Не сейчас» `nojoin`]. Given уже участник Then «Вы уже в группе «{name}».» и кнопка «Открыть группу» `g:{id}`.
  Given код не найден/перевыпущен/не по формату/группа пуста, или payload не `join_<код>` Then «Приглашение
  недействительно или группа больше не существует.»
- **AC-16** When `join:{code}` Then `JoinAsync`; `joined = true`/`false` → редактирование в карточку (AC-6),
  уведомления по 004 AC-16; 404 → редактирование в текст недействительного приглашения; лимит →
  `AnswerAsync(текст лимита, showAlert: true)`. When `nojoin` Then редактирование в «Хорошо, не вступаем.» без клавиатуры.

### Ограничения и паритет
- **AC-17** Callback data всех кнопок ≤ 64 байт: проверка `CallbackData.Create` для самого длинного случая —
  `movienight:kickok:{GUID формата D}:{joinSeq = 999999999}` — и для `newlinkok:{GUID}`, `join:{код 10}`.
  Given `joinSeq` нечисловой или вне `long` Then как неизвестный участник (AC-13).
- **AC-18** Таблица паритета (ниже) покрыта: для каждой строки есть тест бота (эта спека) и тест Mini App (004).

| Функция | Mini App (004) | Бот (005) | Кто |
|---|---|---|---|
| Список групп | «Мои группы» (004 AC-23) | `/groups`, `groups` (AC-2, AC-7) | все |
| Создать группу | «Новая группа» (004 AC-24) | `/newgroup [имя]`, `new` + ответ (AC-3..AC-5) | все |
| Участники, порядок, владелец | «Группа» (004 AC-25) | `g:{id}` (AC-6) | участник |
| Пригласить | «Пригласить», «Скопировать» (004 AC-25) | `invite:{id}` (AC-10) | участник |
| Вступить по ссылке | `startapp=movienight_join_…` (004 AC-28) | `start=movienight_join_…`, `join:{code}` (AC-15, AC-16) | по ссылке |
| Выйти (с передачей владения) | «Выйти из группы» (004 AC-25, AC-26) | `leave`/`leaveok` (AC-14) | участник |
| Переименовать | «Переименование» (004 AC-29) | `rename:{id}` + ответ (AC-11) | владелец |
| Перевыпустить ссылку | «Новая ссылка-приглашение» (004 AC-26) | `newlink`/`newlinkok` (AC-12) | владелец |
| Исключить участника | «Исключить» (004 AC-26) | `members`/`kick`/`kickok` (AC-13) | владелец |

## Контракт бота
- Команды: `/groups` — «мои группы»; `/newgroup [название]` — «создать группу».
- Start: `/start movienight_join_<код 10 символов [A-Za-z0-9]>`.
- Callback data (`movienight:<action>[:<payload>]`), GUID — формат `D` (36 символов):
  `groups`, `new`, `cancel`, `nojoin`, `g:{guid}`, `invite:{guid}`, `leave:{guid}`, `leaveok:{guid}`,
  `rename:{guid}`, `newlink:{guid}`, `newlinkok:{guid}`, `members:{guid}`, `kick:{guid}:{joinSeq}`,
  `kickok:{guid}:{joinSeq}`, `join:{code}`.
- Reply-действия (`MapReply`): `newname` (payload `""`), `rename` (payload = `{guid}`).
- Тексты — в AC (точные строки, без parse mode). Кнопка web_app — только при `WebAppUrl != null`.

## Принятые решения (ответы пользователя)
- **Режим бота — вариант A:** личный чат, команды в меню «/», inline-кнопки, ввод текста по запросу бота. Без
  inline-режима `@bot` и без групповых чатов.
- **Права — создатель-владелец (вариант B):** переименование, перевыпуск ссылки и исключение — только владельцу; в боте
  кнопки владельца показываются только ему и перепроверяются на сервере (AC-9); выход владельца передаёт владение
  следующему по порядку (AC-14).
- **Паритет — полный (вариант A):** таблица паритета Mini App ↔ бот в каждой спеке модуля (AC-18).
- **Порядок:** 003 → 004 → 005, каждая отдельным циклом `/feature`.

## Допущения
- Переходы «список ↔ карточка ↔ участники ↔ подтверждение» редактируют одно сообщение; результат ввода текста и
  приглашение — новые сообщения (приглашение нужно пересылать).
- В тексте приглашения обе ссылки: Mini App (основная по брифу) и бот.
- Участник в callback data адресуется `joinSeq` (id членства), а не `userId`: укладывается в 64 байта и делает
  устаревшую кнопку безопасной после выхода и повторного вступления того же человека.
- Тексты без parse mode: названия групп и имена не требуют экранирования.
