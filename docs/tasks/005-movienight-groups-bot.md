# 005 — MovieNight: группы в боте (дублирование Mini App)

**Статус:** DONE (critic APPROVED, круг 2; ред. 3 — замечания critic, круг 1; см. «Решения по замечаниям critic, круг 1» и «Остаточные замечания»)
**Модуль:** movienight (existing)   **Бриф:** docs/product/movie-night.md (Этап 1, часть 2 из 2;
«Дополнения после проверки Этапа», п. 0)
**Зависит от:** 003 (DONE: `MapReply`, `IBotConversation`, `BotCallbackContext.EditAsync`, `IDeepLinks`, `CallbackData`),
004 (DONE: `IGroupService`, `GroupException`/`GroupError`, `MemberInfo.JoinSeq`, правило получателей уведомлений).

## Исходное описание
Этап 1 (группы) + дополнение: «продублировать функции, которые появятся в Mini App, через inline команды в боте,
чтобы была возможность работать с ботом через контекстное меню в Telegram».

## Цель
Всё, что 004 даёт в Mini App для групп, доступно в личном чате с ботом: команды в меню «/», inline-кнопки, ввод текста
по запросу бота. Бизнес-логика, права и уведомления — только `IGroupService` (004 + один новый метод, BE-1); бот —
тонкий слой `src/Modules/MovieNight/Telegram/`, зависит только от `Application` и контрактов `Bot.Platform`.

## Сценарии
1. `/groups` → «Ваши группы:» с кнопкой на каждую группу и «➕ Создать группу».
2. «Создать группу» → «Как назовём группу? …» → пользователь пишет «Киноклуб» → карточка группы новым сообщением.
3. Карточка: участники по порядку с пометкой владельца, кнопки «Пригласить», «Выйти из группы», «« К списку групп»,
   «Открыть приложение»; владельцу ещё «Переименовать», «Новая ссылка», «Участники» (исключение).
   Переходы между меню — редактированием того же сообщения.
4. «Пригласить» → отдельное сообщение с приглашением и ссылками — для пересылки.
5. Друг открывает `t.me/<bot>?start=movienight_join_<код>` → «Приглашение в группу …» → «Вступить».
6. Владелец: «Участники» → «Исключить Васю» → «Да, исключить».

## Общие правила обработчиков
- Пользователь — `ctx.From.Id`; сервисы — из `ctx.Services` (scope на одно обновление): `IGroupService`,
  `IBotConversation`, `IDeepLinks`.
- Колбэки: `CallbackData.TryParse` делает платформа; модуль получает `Action` и `Payload`. `{id}` в payload —
  `Guid.TryParseExact(…, "D")`; не разобрался → как `GroupNotFound` (AC-8). `{joinSeq}` — `long.TryParse` с
  `NumberStyles.None` и `CultureInfo.InvariantCulture`; не разобрался → как «участник не найден» (AC-13).
- Все callback data строятся только через `CallbackData.Create("movienight", action, payload)` (превышение 64 байт —
  исключение, а не тихая порча кнопки).
- Бот **не валидирует** название сам и не проверяет права сам до вызова сервиса: порядок проверок — сервисный
  (004 AC-10: членство `GroupNotFound` → владелец `NotOwner` → валидация `InvalidName`; 004 AC-16: код → уже участник →
  лимит). Исключение — экраны-подтверждения владельца (`newlink`, `members`, `kick`), которые ничего не меняют: там
  бот вызывает `GetAsync` и сравнивает `group.OwnerId == userId` в том же порядке (членство → владелец → участник).
- Маппинг `GroupException` (для колбэков с `{id}`):
  | `GroupError` | Реакция бота |
  |---|---|
  | `GroupNotFound` | AC-8 |
  | `NotOwner` | AC-9 |
  | `MemberNotFound` | AC-13 («Этот участник уже не в группе») |
  | `CannotRemoveSelf` | `AnswerAsync("Чтобы уйти из группы, используйте «Выйти».", showAlert: true)` + список участников (AC-13) |
  | `GroupLimit` | текст лимита (AC-3, AC-4, AC-16) |
  | `InvalidName` | AC-3, AC-4, AC-11 |
  | `InviteNotFound` | AC-15, AC-16 |
- Колбэк без явного `AnswerAsync` получает пустой ответ от платформы (finally диспетчера) — отдельно вызывать не нужно.
- Уведомления другим участникам шлёт сам сервис (правило получателей — 004 AC-16; тексты — 004 «Контракт бота»).
  Бот исполнителю сам ничего «уведомительного» не шлёт — только ответы из AC.
- Тексты — без parse mode (`OutgoingMessage(text, markup)`, `Html = false`): названия и имена не экранируются.

## Критерии приёмки
В тестах — реальный `Program` с модулем, реальная БД модуля, обновления через `POST /bot/webhook`, захват
`IMessageSender` (`SendAsync` и `EditAsync`) и захват HTTP-запросов к Bot API (`answerCallbackQuery`,
`setMyCommands`) — см. «Тестовая стратегия». Имена, порядок, правило получателей уведомлений — как в 004.
Здесь и далее callback data указана без префикса `movienight:`; полная строка — `movienight:<action>[:<payload>]`.

### Команды и создание
- **AC-1** Given модуль зарегистрирован и `Bot:PublicUrl` задан When старт Host Then запрос `setMyCommands` содержит
  `[start, help, groups — «мои группы», newgroup — «создать группу»]` (в этом порядке); `/help` отвечает
  «Команды:\n/start — открыть приложение\n/help — список команд\n/groups — мои группы\n/newgroup — создать группу».
  `MovieNightModule` переопределяет `MapBot` (004 AC-1a в части «MapBot не переопределяется» отменён этой спекой).
- **AC-2** Given пользователь создал группу A (2 участника, он владелец), затем вступил в группу B (2 участника,
  владелец — другой) When `/groups` Then **новое** сообщение «Ваши группы:»,
  inline-клавиатура: по строке на группу в порядке 004 AC-5 (последняя вступленная — сверху) с текстом «{name} · {N}»
  (у групп, где он владелец, — «★ {name} · {N}») и callback `g:{id}`; последняя строка — «➕ Создать группу» (`new`).
  Given групп нет Then «У вас пока нет групп. Создайте группу и пригласите друзей.» и только «➕ Создать группу».
- **AC-3** Given `/newgroup   Киноклуб  ` Then `CreateAsync(user, "Киноклуб")` (аргументы уже trim платформой),
  ответ — карточка (AC-6) **новым** сообщением. Given `/newgroup` без аргументов Then новое сообщение «Как назовём
  группу? Отправьте название одним сообщением (до 64 символов).» с кнопкой «Отмена» (`cancel`) и
  `ExpectReplyAsync(user, "movienight", "newname", null)`. Given аргумент невалиден по 004 AC-3 (в т.ч. содержит
  перевод строки, длиннее 64) Then «Название должно быть от 1 до 64 символов, без переводов строк.», группа не создана,
  ожидание не ставится. Given лимит 004 AC-4 Then «Можно состоять не больше чем в 20 группах.», ожидание не ставится.
- **AC-4** Given ожидание `newname` When текст «Киноклуб» Then группа создана, карточка новым сообщением. When текст
  невалиден (например, 65 символов) Then «Название должно быть от 1 до 64 символов, без переводов строк. Попробуйте ещё
  раз.» и `ExpectReplyAsync(user, "movienight", "newname", null)` снова (следующий валидный текст создаёт группу).
  When лимит Then текст лимита, ожидание не ставится (следующий текст → платформенное «Я понимаю только команды…»).
- **AC-5** When `new` Then **новое** сообщение-вопрос и ожидание — как AC-3 без аргументов (исходное сообщение не
  меняется). When `cancel` Then `CancelAsync(user)`, сообщение с кнопкой редактируется в «Хорошо, отменили.» без
  клавиатуры; следующий текст → «Я понимаю только команды…». Повторный `cancel` (ожидания нет) — то же редактирование.

### Карточка и навигация
- **AC-6** When `g:{id}` от участника Then сообщение **редактируется** в карточку:
  ```
  Группа «{name}»
  Участники (по порядку вступления):
  1. Аня (вы) — владелец
  2. Петя
  ```
  (строка участника — «{position}. {displayName}» + « (вы)» у себя + « — владелец» у `IsOwner`; имена — 004 AC-7).
  Клавиатура не-владельца (по строке на кнопку): «Пригласить» `invite:{id}`; «Выйти из группы» `leave:{id}`;
  «« К списку групп» `groups`; «Открыть приложение» — `web_app` на `IDeepLinks.WebAppUrl` (строки нет при `null`).
  Клавиатура владельца: «Пригласить»; «Переименовать» `rename:{id}`; «Новая ссылка» `newlink:{id}`; «Участники»
  `members:{id}` (только если участников > 1); «Выйти из группы»; «« К списку групп»; «Открыть приложение».
  Карточка как результат создания/переименования/вступления по `/start` — тот же текст и клавиатура.
- **AC-7** When `groups` Then сообщение редактируется в список (тексты и клавиатура AC-2, включая пустой вариант).
  Повторное нажатие без изменений — тот же `EditAsync`, без исключений (статус «not modified» обрабатывает платформа,
  003 AC-11).
- **AC-8** Given `{id}` группы, где пользователь не участник, группы нет, группа пуста, или `{id}` не GUID формата `D`
  When любой колбэк с `{id}` (`g`, `invite`, `leave`, `leaveok`, `rename`, `newlink`, `newlinkok`, `members`, `kick`,
  `kickok`) Then `AnswerAsync("Вы не состоите в этой группе", showAlert: true)` и сообщение редактируется в список
  (AC-2); изменений в БД нет. Проверяется раньше AC-9 (не-участник на колбэке владельца получает AC-8).
- **AC-9** Given участник, не владелец (например, старое сообщение после смены владельца) When колбэк владельца
  (`rename`, `newlink`, `newlinkok`, `members`, `kick`, `kickok`) Then `AnswerAsync("Это может сделать только владелец
  группы.", showAlert: true)`, сообщение редактируется в актуальную карточку (AC-6, клавиатура не-владельца);
  изменений нет, ожидание ответа не ставится. Проверяется раньше разбора `{joinSeq}` и наличия участника.
- **AC-10** When `invite:{id}` (любой участник) Then **новое** сообщение без клавиатуры:
  «Присоединяйся к группе «{name}» в Киновечере!\nОткрыть приложение: {miniAppLink}\nЧерез бота: {botLink}»
  (ссылки — `GroupDetails.MiniAppLink`/`BotLink` текущего кода), исходное сообщение не меняется, ответ на колбэк —
  пустой. Given хотя бы одна из ссылок `null` (на практике обе сразу — `Bot:Username` не задан) Then `AnswerAsync("Ссылка-приглашение недоступна",
  showAlert: true)`, сообщение не шлётся.

### Действия владельца
- **AC-11** When `rename:{id}` (владелец) Then **новое** сообщение «Новое название для группы «{name}»? Отправьте
  одним сообщением (до 64 символов).» с «Отмена» (`cancel`) и `ExpectReplyAsync(user, "movienight", "rename", "{id}")`
  (`{id}` — формат `D`). Ответ текстом → `RenameAsync(user, id, text)`:
  успех → новое сообщение-карточка с новым именем, уведомлений нет;
  `InvalidName` → «Название должно быть от 1 до 64 символов, без переводов строк. Попробуйте ещё раз.» и ожидание
  `rename` с тем же payload снова;
  `GroupNotFound` (пользователь больше не участник, payload не GUID) → новое сообщение «Вы не состоите в этой группе»,
  ожидание не ставится;
  `NotOwner` → новое сообщение «Это может сделать только владелец группы.», ожидание не ставится.
  Порядок 004 AC-10 обязателен: не-владелец с невалидным названием получает «…только владелец…», не-участник с
  невалидным — «Вы не состоите…».
- **AC-12** When `newlink:{id}` (владелец) Then редактирование в «Старая ссылка перестанет работать. Создать новую?» с
  [«Да, новая ссылка» `newlinkok:{id}`] [«Отмена» `g:{id}`] (по строке на кнопку). When `newlinkok:{id}` Then
  `RegenerateInviteAsync`; сообщение редактируется в карточку; `AnswerAsync("Создана новая ссылка")`; **новое**
  сообщение-приглашение (текст AC-10) со ссылками нового кода. Старый код после этого: `/start movienight_join_<старый>`
  → AC-15 «недействительно». Given хотя бы одна из ссылок `null` (как в AC-10) Then код перевыпущен, карточка, `AnswerAsync("Создана новая ссылка")`,
  приглашение не шлётся.
- **AC-13** When `members:{id}` (владелец) Then редактирование в «Участники группы «{name}»:» + клавиатура: на каждого
  участника, кроме себя, по порядку — строка «Исключить {displayName}» `kick:{id}:{joinSeq}`; последняя —
  «« К группе» `g:{id}`. (Единственный участник — только «« К группе».)
  When `kick:{id}:{joinSeq}` Then редактирование в «Исключить {displayName} из группы «{name}»?» с
  [«Да, исключить» `kickok:{id}:{joinSeq}`] [«Отмена» `members:{id}`].
  When `kickok:{id}:{joinSeq}` Then `RemoveMembershipAsync(user, id, joinSeq)` (BE-1); редактирование в актуальный
  список участников (AC-13 заново); `AnswerAsync("{displayName} исключён(а) из группы")` (имя — возвращённое
  сервисом); уведомления — 004 AC-12 (исключённому «Вас исключили из группы «{name}».», остальным, кроме исполнителя,
  «{displayName} больше не в группе «{name}».»).
  Given членства с этим `{joinSeq}` в группе нет (участник вышел, исключён, вышел и вступил снова — у него новый
  `JoinSeq`), или `{joinSeq}` не разобран, на `kick` или `kickok` Then `AnswerAsync("Этот участник уже не в группе",
  showAlert: true)` и редактирование в актуальный список участников; повторно вступивший **не** исключается.
  Given `{joinSeq}` — членство самого владельца: на `kick` — как «уже не в группе»; на `kickok` — `CannotRemoveSelf`
  (таблица маппинга).
- **AC-13a** Given двойное нажатие «Да, исключить» (два `kickok` подряд) Then первый исключает и уведомляет, второй —
  «Этот участник уже не в группе»; уведомления ушли один раз.

### Выход
- **AC-14** When `leave:{id}` Then редактирование в «Выйти из группы «{name}»?» (владелец при других участниках:
  «Выйти из группы «{name}»? Владельцем станет {displayName участника с position = 2}.») с [«Да, выйти» `leaveok:{id}`]
  [«Отмена» `g:{id}`]. When `leaveok:{id}` Then `LeaveAsync`, редактирование в «Вы вышли из группы «{name}».» + кнопка
  «« К списку групп» (`groups`). Уведомления и передача владения — 004 AC-18, AC-19 (последний участник — без
  уведомлений, 004 AC-22). Повторный `leaveok` → AC-8.

### Вступление через бота
- **AC-15** Given `/start movienight_join_AB12cd34EF` (платформа передаёт модулю payload `join_AB12cd34EF`; код
  действует, пользователь не участник) Then `GetInviteAsync`, новое сообщение «Приглашение в группу «{name}»\nУчастники:
  {memberNames через ", "}» с [«Вступить» `join:AB12cd34EF`] [«Не сейчас» `nojoin`]. Given уже участник Then «Вы уже в
  группе «{name}».» и кнопка «Открыть группу» `g:{groupId}`. Given payload не `^join_[A-Za-z0-9]{10}$`, код не найден,
  перевыпущен, другого регистра, или группа пуста (`InviteNotFound`) Then «Приглашение недействительно или группа
  больше не существует.» без клавиатуры. (Payload, не прошедший платформенную проверку `start`, до модуля не доходит —
  платформа отвечает приветствием, 002/003.)
- **AC-16** When `join:{code}` Then `JoinAsync`; `Joined = true` → редактирование в карточку (AC-6), уведомления по
  004 AC-16; `Joined = false` → редактирование в карточку, уведомлений нет; `InviteNotFound` (в т.ч. `{code}` не по
  формату) → редактирование в «Приглашение недействительно или группа больше не существует.» без клавиатуры;
  `GroupLimit` → `AnswerAsync("Можно состоять не больше чем в 20 группах.", showAlert: true)`, сообщение не меняется.
  When `nojoin` Then редактирование в «Хорошо, не вступаем.» без клавиатуры.

### Ограничения и паритет
- **AC-17** Callback data всех кнопок ≤ 64 байт UTF-8. Самый длинный случай — `movienight:kickok:{GUID D}:999999999`
  = 11 + 7 + 36 + 1 + 9 = **64** байта: `CallbackData.Create` не бросает; при `joinSeq = 1000000000` (10 цифр, 65 байт)
  бросает `ArgumentException` (граница зафиксирована, см. 004 «Допущения»). Также не бросает для
  `newlinkok:{GUID}` (57), `members:{GUID}` (55), `join:{код 10}` (26). Нечисловой `joinSeq` или вне `long` — AC-13.
- **AC-18** Таблица паритета (ниже) покрыта: для каждой строки есть тест бота (эта спека) и тест Mini App (004).
  Набор зарегистрированных модулем маршрутов (через публичный `IBotRouteBuilder`, см. TEST-6) равен ровно: команды
  `[groups, newgroup]`; колбэки `{groups, new, cancel, nojoin, g, invite, leave, leaveok, rename, newlink, newlinkok,
  members, kick, kickok, join}`; reply `{newname, rename}`; один start-обработчик.

|---|---|---|---|

| Участники, порядок, владелец | «Группа» (004 AC-25) | `g:{id}` (AC-6) | участник |
| Пригласить | «Пригласить», «Скопировать» (004 AC-25) | `invite:{id}` (AC-10) | участник |
| Вступить по ссылке | `startapp=movienight_join_…` (004 AC-27, AC-28) | `start=movienight_join_…`, `join`, `nojoin` (AC-15, AC-16) | по ссылке |
| Выйти (с передачей владения) | «Выйти из группы» (004 AC-25, AC-26) | `leave`/`leaveok` (AC-14) | участник |
| Переименовать | «Переименование» (004 AC-29) | `rename:{id}` + reply `rename` (AC-11) | владелец |

## Контракт API
HTTP-эндпоинтов не добавляется; поведение существующих не меняется (все тесты 004 остаются зелёными).

Расширение `IGroupService` (аддитивно, для бота; API его не использует):
```csharp
// src/Modules/MovieNight/Application/IGroupService.cs
/// <summary>Исключение по id членства (JoinSeq). Владелец. Возвращает displayName исключённого (правило 004 AC-7).</summary>
/// <remarks>Порядок проверок: GroupNotFound (вызывающий не участник) → NotOwner → MemberNotFound (в группе нет
/// членства с таким JoinSeq) → CannotRemoveSelf (JoinSeq — членство вызывающего). Транзакция, повторы и уведомления —
/// как у RemoveMemberAsync (004 AC-12, AC-16).</remarks>
Task<string> RemoveMembershipAsync(long userId, Guid groupId, long joinSeq, CancellationToken ct);
```
Зачем: при «прочитать `userId` по `joinSeq` → `RemoveMemberAsync(userId)`» между шагами участник мог выйти и вступить
снова (новый `JoinSeq`), и устаревшая кнопка исключила бы новое членство. Проверка и удаление по `JoinSeq` — в одной
транзакции.

## Контракт бота
- Команды (в этом порядке): `/groups` — «мои группы»; `/newgroup [название]` — «создать группу».
- Start: `MapStart` модуля; payload `join_<код [A-Za-z0-9]{10}>`.
- Callback data (`movienight:<action>[:<payload>]`), GUID — формат `D` (36 символов), `joinSeq` — десятичное `long`:
  `groups`, `new`, `cancel`, `nojoin`, `g:{guid}`, `invite:{guid}`, `leave:{guid}`, `leaveok:{guid}`,
  `rename:{guid}`, `newlink:{guid}`, `newlinkok:{guid}`, `members:{guid}`, `kick:{guid}:{joinSeq}`,
  `kickok:{guid}:{joinSeq}`, `join:{code}`.
- Reply-действия (`MapReply`): `newname` (payload `""`), `rename` (payload = `{guid}`).
- Сообщения: новое (`ReplyAsync`) — ответ на команду/start, результат ввода текста, вопрос о названии, приглашение;
  редактирование (`EditAsync`) — все переходы по кнопкам, кроме `new`, `rename`, `invite` (и доп. приглашения в
  `newlinkok`).
- Тексты — точные строки из AC (в `GroupBotTexts` как `const`/форматтеры), без parse mode; исключение — текст
  `/help`: его строит платформа (`UpdateDispatcher.BuildHelp`) из описаний команд, модуль отвечает только за
  описания команд (AC-1). Кнопки:
  «➕ Создать группу», «Отмена», «Пригласить», «Выйти из группы», «« К списку групп», «Открыть приложение»,
  «Переименовать», «Новая ссылка», «Участники», «Да, новая ссылка», «Исключить {displayName}», «« К группе»,
  «Да, исключить», «Да, выйти», «Вступить», «Не сейчас», «Открыть группу».

## Тестовая стратегия (обязательна для TEST-*)
`IBotApi`, `BotApiMock`, `BotHarness` — `internal` в `Bot.Platform` (`InternalsVisibleTo` только `Bot.Platform.Tests`);
`InternalsVisibleTo` для тестов модуля **не добавляется** (тесты модуля опираются только на публичные контракты, как
будет и у следующих модулей). Поэтому бот тестируется end-to-end через публичные точки:
1. **Вход:** `POST /bot/webhook` с заголовком `X-Telegram-Bot-Api-Secret-Token: test-webhook-secret` и телом —
   JSON обновления (`TestUpdates.ToJson(...)`; `TestUpdates.cs` подключается ссылкой на исходники, как остальные
   общие хелперы). Webhook дожидается обработки до ответа 200 — после ответа все эффекты (БД, отправки) уже случились.
   Ответ всегда 200 даже при исключении в обработчике — поэтому тесты проверяют эффекты, а для «без исключений»
   (AC-7) — отсутствие Error в `LogCapture`.
2. **Send/Edit:** `IMessageSender` → `RecordingSender` (уже в фабрике 004), дополнить записью `EditAsync`
   (`chatId`, `messageId`, `OutgoingMessage`) в общий упорядоченный журнал; клавиатура проверяется по объекту
   `InlineKeyboardMarkup` (тексты, `CallbackData`, `WebApp.Url`).
3. **answerCallbackQuery и setMyCommands:** идут через `IBotApi` → `TelegramBotApi` → именованный `HttpClient`
   `"telegram"`. В `ConfigureTestServices`: `services.AddHttpClient("telegram").ConfigurePrimaryHttpMessageHandler(() =>
   FakeTelegramHandler)` — фейковый `HttpMessageHandler` записывает метод Bot API (последний сегмент пути) и JSON-тело,
   отвечает `{"ok":true,"result":true}`. Ассерты: `callback_query_id`, `text`, `show_alert` (отсутствие поля =
   `false`); для `setMyCommands` — массив `commands[].command/description`. Заодно гарантирует, что тесты не ходят в
   реальный Telegram. Сверить: замещение primary handler поздней регистрацией (Microsoft.Extensions.Http), формат тела
   запроса Telegram.Bot 22.10.4 (JSON, snake_case).
4. **Варианты конфигурации** — свойства `MovieNightFactory`: `Username = null` (ссылки `null`), `PublicUrl`
   (`https://example.test/` → `WebAppUrl` и запуск `BotSetupService`, который уйдёт в фейковый handler). `IDeepLinks` —
   реальный.
5. **Имена:** диспетчер на каждом обновлении обновляет запись реестра именем из `from`. Поэтому обновления для
   пользователя N строятся с тем же `firstName` (и `lastName: null`), что и посев (`Аня`, `Петя`, …) — свой хелпер
   `BotUpdates` в модуле поверх `TestUpdates.Private/Callback/Command`. Посев групп — через HTTP API 004
   (`GroupWithAsync`) или через бота.
6. **Набор маршрутов (AC-18):** `IBotRouteBuilder` публичен — тестовый `RecordingRouteBuilder` получает вызовы
   `((IBotModule)new MovieNightModule()).MapBot(builder)` без DI.
7. **Ожидание ответа:** проверяется поведением (следующий текст обрабатывается reply-обработчиком или получает
   «Я понимаю только команды. Список команд — /help»), без доступа к таблице `PendingReplies`.

## Решения по замечаниям critic, круг 1
1. **Текст `/help` не входит в `GroupBotTexts`.** `GroupBotTexts` хранит все строки из AC этой спеки, кроме текста
   `/help`: его собирает платформа (`UpdateDispatcher.BuildHelp`, спека 002/003) из описаний команд, переданных при
   регистрации. Модуль отвечает только за описания команд `/groups` и `/newgroup` (AC-1). Правок кода не требуется.
2. **Недоступность приглашения: «любая из ссылок `null` → недоступно».** Условие AC-10 и ветки «без ссылок» в
   `newlinkok` (AC-12) — `MiniAppLink is null || BotLink is null` (как в реализации, `GroupBotRoutes.cs`). По 003
   AC-13 и `IDeepLinks` обе ссылки зависят только от `Bot:Username`: без `Bot:MiniAppShortName` Mini App-ссылка
   строится как `https://t.me/{Username}?startapp=…` (не `null`). Значит, фактически ссылки бывают `null` только
   одновременно (нет `Bot:Username`), и «любая `null`» эквивалентно «обе `null»`; проверка через `||` — защитная на
   случай будущих изменений `IDeepLinks`, чтобы не отправить приглашение с текстом «null». Отсутствие
   `Bot:MiniAppShortName` приглашение **не** блокирует. Правок кода не требуется; тесты — только вариант
   `Username = null` (частичный `null` при текущем `IDeepLinks` недостижим и не тестируется).

## Допущения
- Переходы «список ↔ карточка ↔ участники ↔ подтверждение» редактируют одно сообщение; результат ввода текста,
  вопрос о названии и приглашение — новые сообщения (приглашение нужно пересылать).
- В тексте приглашения обе ссылки: Mini App (основная по брифу) и бот.
- Участник в callback data адресуется `joinSeq` (id членства), а не `userId`: укладывается в 64 байта и делает
  устаревшую кнопку безопасной после выхода и повторного вступления того же человека.
- Тексты без parse mode: названия групп и имена не требуют экранирования.
- `/newgroup` без аргументов и `new` не проверяют лимит заранее — лимит проверяет `CreateAsync` при ответе (AC-4).
- `cancel` снимает любое ожидание пользователя (`IBotConversation` хранит одно на пользователя) и всегда редактирует
  сообщение, даже если ожидания уже нет.
- Ответ бота о недоступной группе — «Вы не состоите в этой группе» (а не «Группа не найдена.» из API): существование
  чужой группы так же не раскрывается.
- «Открыть приложение» открывает корень Mini App (`WebAppUrl`); `web_app`-кнопка не несёт `start_param`.

## Остаточные замечания (MINOR, не блокируют)
